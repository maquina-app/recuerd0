# Recuerd0 user test: 2026-11-04

I tested as a new user: read the marketing site, signed up, then used the product in a browser. I did not read the application source. Every issue below was reproduced in the running app, unless its entry says otherwise.

**Environment:** local dev server, `MULTI_TENANT_ENABLED=true`, Chrome via Playwright, desktop (1440px) and phone (390px), light and dark. It was not run against production, so anything that only exists there, such as billing, could not be seen.

**Evidence:** screenshots are in `.playwright-mcp/audit-*.png` (gitignored), cited as `audit-NN`.

**Severity**

- **High:** crash, wrong or corrupted data, a false success message, or a legal/trust contradiction.
- **Medium:** a real user gets confused or blocked, or a marketing claim doesn't match the product.
- **Low:** polish.

## High

### U-01: Accepting an invitation with an existing email crashes

**Reproduce**
1. As an admin, go to Account > Generate Invitation Link.
2. Open the link in a logged-out browser.
3. Enter an email that already has an account, plus a valid password, and submit.

**Actual:** an unhandled `ActiveRecord::RecordNotUnique` in `InvitationsController#create` (`UNIQUE constraint failed: users.email_address`). In production this would be an error page. Normal signup handles the same case with an inline error.

**Why it's a problem:** people who already use Recuerd0 are the most likely invitees, and they hit a crash. They also have no way to accept: the invitation page only offers account creation, even when you're already signed in.

**Expected:** an inline error at minimum. Better: "You already have an account, sign in to accept", or a clear statement that one email can only belong to one account.

### U-02: "Unarchive" on a deleted workspace falsely reports success

**Reproduce**
1. Archive a workspace.
2. Under Archived, open its menu and choose Delete, then confirm.
3. Go to Deleted. The row is labelled **Archived** and its menu offers **Unarchive / Delete**, not Restore / Delete permanently.
4. Click Unarchive.

**Actual:** the toast says "Unarchived QA Lifecycle" and you land on Workspaces, but the workspace isn't there. It is still deleted. Going back to Deleted, the menu now shows Restore / Delete permanently. Opening the workspace before step 4 also says "This workspace is archived", with no mention that it was deleted. (`audit-27`)

**Why it's a problem:** the recovery screen for deleted data reports a success that didn't happen. Someone trying to rescue a workspace can reasonably conclude it's gone. The "Delete" action in that state is also ambiguous: it isn't clear whether it's permanent.

**Expected:** Deleted always shows the Deleted state with Restore and Delete permanently. Restore should work in one step and say which state the workspace returns to.

### U-03: A code block after a list is silently corrupted

**Reproduce**
1. New Memory. In the editor type `- one`, Enter, `two`, Enter, Enter. (The second Enter ends the list.)
2. Type a fenced code block: ` ```ruby `, `puts 1`, ` ``` `.
3. Click Create.

**Actual:** the editor shows a proper code block, but the saved source is:

```text
- one
- two
```ruby
puts 1
```
```

No blank line separates the list and the fence, so it renders as inline code inside the last bullet: `<li>two <code>ruby puts 1</code></li>`. The word `ruby` becomes part of the code. Adding one more blank line renders correctly. (`audit-11`, `audit-14`, `audit-44`; correct variant in `audit-43`)

**Why it's a problem:** the editor preview and the saved result disagree, and the malformed Markdown is what agents receive. This is the core content of the product.

**Expected:** what the editor shows is what gets saved. The editor should keep or insert the blank line when leaving a list.

### U-04: "View Markdown" on v1 returns the current version

**Reproduce**
1. Create a memory, then use New Version until there's a v2 or later.
2. Edit the current version and add a unique word.
3. Open v1. The page correctly does not contain the word.
4. Open the menu and choose View Markdown.

**Actual:** the Markdown contains the word from the current version. "Copy markdown" on the same page correctly copies v1, and `/markdown` on a middle version (v2) correctly returns v2. Only the first version is affected.

**Why it's a problem:** on a page labelled "You are viewing v1", two actions return different content. You could copy or hand off the wrong version of a decision without noticing.

**Expected:** `/memories/<id>/markdown` returns the content of the version in the URL.

### U-05: Memory counts include versions

**Reproduce:** create a memory with 3 versions in a workspace that has 4 other memories, then view the workspace.

**Actual:** the header and the Workspaces list say **7 memories**; the filter says **All 5**. Later in the same test the header said 10 while the filter said 7. The inflated number also appears in search results. (`audit-32`)

**Why it's a problem:** two different counts on one screen make the data look unreliable, and creating a version looks like adding memories. The product also advises restructuring at around 20 memories, so an inflated count sends the wrong signal.

**Expected:** "memories" counts distinct memories everywhere. Show versions as a separate number if useful.

### U-06: The 30-day recovery window can't be used

**Reproduce**
1. Account > Delete Account > Confirm.
2. Try to sign in again with the same credentials.
3. Register again with the same email.

**Actual**
- Confirmation is a generic "Confirm / Confirm" dialog with no typed confirmation or password, for the most destructive action in the product.
- You land on the marketing home page with no message saying anything happened.
- Sign-in fails with "Try another email address or password", as if the password were wrong.
- The same email can register immediately as a brand-new, empty account. (The old data stayed isolated: its workspace returned 404 for the new account.)
- There's no recovery path. Any finished export becomes unreachable, because the Download button lives on the account page.

**Why it's a problem:** the Terms say data is retained for 30 days, "giving you time to change your mind or export your data". A user can do neither.

**Expected:** decide on one of these and make the UI and legal text match:
- A real grace period: signing in shows "Scheduled for deletion on <date>" with Restore and Export.
- Immediate deletion, with the Terms changed to say so.

In both cases, require stronger confirmation and show a clear final message.

### U-07: Legal pages contradict each other and the product

| Topic | One place says | Another place says |
|---|---|---|
| Account deletion | Privacy: "all data permanently removed upon account closure" | Terms and the Account page: retained or removed "after 30 days"; the dialog also says "cannot be undone" |
| Analytics | Privacy: "We do not use third-party analytics"; its meta description says "No tracking" | Every page loads a script from `plausible.maquina.app` |
| Export | Terms: "export your data at any time" | Account page: "0 of 2 exports used this month" |
| How to export | Privacy: "download your data via the API at any time" | `/api-docs` doesn't mention export at all |
| Who it's for | Terms: "for individual use" | Marketing and pricing: teams of up to 10 |

All three legal pages say "Last updated: February 2026".

Plausible may be self-hosted and privacy-friendly, in which case the claim may be defensible. Even so, the policy should disclose it, because anyone inspecting network traffic will see it. This table is a product reading, not legal advice.

**Why it's a problem:** the audience is privacy-conscious developers, and these are the pages they check before trusting a service with their knowledge base.

**Expected:** one accurate statement per topic, with an updated revision date.

## Medium: versioning

"Versioned" is a headline feature, and this is where the product felt most confusing.

### U-08: Edit overwrites the version with no history

**Reproduce:** open a memory, click Edit, change the content, Save.

**Actual:** the version number doesn't change and the old text is gone. Versions only appear through a separate menu action. The MCP docs describe versions as "immutable", and the landing page promises to "track how your project knowledge evolves, like Git".

**Why it's a problem:** the obvious button (Edit) is the one that destroys history. A user who trusts the marketing will lose content.

**Expected:** make saving a new version the default or an obvious choice on Save, for example "Save as new version" vs "Fix in place". At minimum, say on the edit screen that it overwrites v*N*.

### U-09: "New Version" creates an identical copy

**Reproduce:** menu > New Version > confirm.

**Actual:** you immediately have a v2 identical to v1, without being asked what changed. You then press Edit, which overwrites v2 (see U-08). (`audit-13`, `audit-14`)

**Why it's a problem:** this order is backwards. It leaves empty, no-difference versions in the history.

**Expected:** New Version opens the editor and creates the version on save.

### U-10: "Branch" isn't a branch

**Reproduce:** with v1 and v2, go to Versions > Branch on v1 > Confirm.

**Actual:** this creates v3 from v1 and makes it current, so v2's work is no longer what you see or what agents read. The dialog says only "Confirm / Create a new version from v1? / Confirm", and nothing warns that the current version changes. Numbering stays linear. (`audit-17`, `audit-18`)

**Why it's a problem:** developers expect a branch to be parallel work that leaves the current state alone. This is really a restore.

**Expected:** name it "Restore as new version" and say "v3 will become current. v2 stays in history."

### U-11: No way to see what changed

**Reproduce:** open a Versions page with two or more versions.

**Actual:** each version shows a preview of flattened raw Markdown (`## Deploy notes We deploy with **Kamal**…`). There's no diff or compare, and no field for why a version was made. (`audit-18`)

**Why it's a problem:** version history has little value if you can't tell versions apart without opening each one.

**Expected:** a diff against the previous version, plus an optional change note.

### U-12: Version URLs and dates are inconsistent

**Reproduce:** create versions, then compare the URLs and the dates shown on each.

**Actual**
- Each version has its own URL (`/memories/635`, `/636`, `/637`), so a saved link stays on an old version.
- "Created" on the current version resets to when that version was made, so the memory looks newer than it is.
- v1 shows an "Updated" time that reflects later activity, though v1 didn't change.
- The v1 page says "Switch to the current version to make changes", but opening `/memories/<v1>/edit` directly still works, and saving silently changes the current version.

**Expected:** a stable URL that always opens the latest version, with explicit URLs for specific versions. Show the memory's original creation date separately from the version date. Redirect the old version's edit URL.

## Medium: creating and linking memories

### U-13: Blank memories are created in one click

**Reproduce:** New Memory > Create without entering anything. Separately, `POST /workspaces/:id/memories.json` with `{"memory":{"title":""}}`.

**Actual:** the web form creates "Untitled Memory" with no content and a success toast. The API returns 201 with `"title":""`. (`audit-10`)

**Why it's a problem:** the marketing promises that "every memory earns its place", yet empty memories can reach agents. The two surfaces also treat the same blank input differently.

**Expected:** require a title or some content, on web and API alike.

### U-14: Link search only runs on Enter, with no hint

**Reproduce:** on a memory, click Link a memory, then type a search term and wait.

**Actual:** nothing happens and no request is sent. Pressing Enter shows results. There's no button or hint, and every other search in the app runs as you type. The input also isn't focused when the panel opens. (`audit-21`, `audit-22`)

**Why it's a problem:** the feature looks broken.

**Expected:** search as you type like the others, and focus the input on open.

### U-15: "Saved" appears on a form that was never saved

**Reproduce:** open New Memory.

**Actual:** the status next to Create says "Saved" before anything has happened. Typing changes it to "Unsaved changes". There's no autosave, and a refresh would lose the draft unless the leave warning stops you. (`audit-09`)

**Why it's a problem:** "Saved" implies your work is safe, or that autosave exists.

**Expected:** show nothing until there are changes.

## Medium: onboarding

### U-16: Setup progress doesn't match what you're asked to do

**Reproduce:** sign up, read the banner, open "Show me how", then create a memory in the web UI.

**Actual**
- The banner says "0 of 2", but the drawer lists five items marked 1, •, •, •, 2, so it's unclear what counts.
- Creating a memory in the browser moves progress to "1 of 2", while the banner still says "connect an agent" and no agent is connected.
- Step 2 says "Ask your agent", but the browser counts too.
- An invited member sees the same "Finish setting up" banner, already at "1 of 2", on every page.

(`audit-05`, `audit-06`)

**Expected:** name the two steps, show which is done, and apply progress per person.

### U-17: Setup instructions point at the wrong server

**Reproduce:** on a local instance, open the drawer, then compare it with `/start` and `/cli`.

**Actual**
- The Chat tab always shows `https://recuerd0.ai/mcp`, even on another instance. Self-hosters would connect their agent to the wrong server.
- The Terminal tab's `recuerd0 account add personal --token <token>` has no `--api-url`.
- `/start` and `/cli` include `--api-url https://your-server.com`, a self-host placeholder, in docs that cloud customers read first.

(`audit-07`)

**Expected:** generate the URL from the current instance. Inside the app, fill in the real URL and workspace ID so commands can be copied as they are.

### U-18: The token form defaults to the wrong permission

**Reproduce:** follow the drawer's "Create a full-access token" to Profile and create a token without changing anything.

**Actual:** the form defaults to Read Only, so a user following the instructions gets a token their agent can't write with unless they notice. A blank description is accepted and listed as "Untitled", which makes tokens hard to tell apart later. (`audit-29`)

**Expected:** arriving from setup preselects Full Access and suggests a name.

### U-19: New workspaces aren't actually blank

**Reproduce:** create a workspace with New Workspace.

**Actual:** it already contains an auto-pinned "Map — how this workspace is kept" memory, marked "Source: system". You aren't told or asked. `/start` only describes seeded content for a new account, and says "a blank workspace is a fine workspace". (`audit-25`)

**Why it's a problem:** a surprise memory that also gets served to agents. "Source: system" is internal-sounding language too.

**Expected:** offer "Start with a map" on the form, or at least document it and explain it on first view.

## Medium: teams and accounts

### U-20: Invitation links are reusable, with no way to revoke them

**Reproduce:** generate a link, join with it, then open the same link again logged out.

**Actual:** the signup form still appears. The page says "Share this link with the person you want to invite", but the link stays usable until it expires in 7 days. There's no list of active links and no revoke button. I did not test whether generating a new link invalidates the old one.

**Why it's a problem:** a forwarded link gives anyone access to all the account's workspaces.

**Expected:** either single-use links, or say clearly that it's a team link and offer revoke.

### U-21: Members can delete an admin's workspaces

**Reproduce:** as a member, open a workspace the admin created, then choose Workspace actions > Delete.

**Actual:** it succeeds. The member also sees Archive and Edit. The marketing mentions "admin and member roles", but nothing explains what a member can't do.

**Decision (2026-11-04):** users can delete only what they own. Admins can delete anything.

**Requirements**
- **Creator:** show who created each workspace and memory in the UI. Check whether a creator is already recorded; if it isn't, start recording it.
- **Items covered:** workspaces and memories. A memory created through the API or MCP belongs to the person whose token or connection created it.
- **Actions covered:** delete, permanent delete, version purge and archive.
- **Enforcement:** hide these actions from members on items they don't own, and have the server reject them too, so a direct request can't get around the hidden button. This applies on web, REST and MCP.
- **Explanation:** describe the rule where people invite others.

- **Items with no recorded creator:** these belong to the account admin, including the seeded "My Workspace".

### U-22: Confusing invitation page wording

**Reproduce:** open an invitation for an account whose name was never changed.

**Actual:** "Join qa-newuser / Create your account to join this workspace". The account name defaults to the owner's email prefix, and you're joining an account, not a workspace. This page also lacks the Terms and Privacy line shown on normal signup.

**Expected:** ask for an account or team name at signup, or show "Join <owner email>'s team". Use the word account, and show the legal line.

### U-23: Profile promises email management, but there's no email field

**Reproduce:** open Profile.

**Actual:** "Manage your name and email address", followed by only a Name field. I found no way to change your email anywhere. (`audit-28`)

**Expected:** add email change with verification, or fix the copy.

## Medium: marketing vs product

### U-24: "Six tools" vs thirteen

The landing page says "Six tools cover reading, searching, and writing". `/mcp` says "thirteen tools. Eight read, five write".

**Expected:** thirteen, or remove the number so it doesn't go stale.

### U-25: Semantic search is both "on the roadmap" and documented as working

The landing page says "semantic search (on the roadmap)". `/mcp` documents "up to five memories close in meaning" being added when a search finds fewer than three matches.

**Expected:** one accurate story. If it's optional or behind a setting, say so.

### U-26: "Start free" has no visible terms

The hero CTA says "START FREE". Pricing shows Cloud at $15/month and only Self-Hosted as free, with no mention of a trial. Signup never mentions a plan or card, and the Account page shows no plan. I also saw no email verification at signup.

This may simply be hidden in dev, so please check it against production.

**Why it's a problem:** people can't tell what they've signed up for or when they'd be charged.

**Expected:** state the trial length and what happens at the end, on the CTA or next to it, and show plan status under Account.

### U-27: "No data leaving your network" on a cloud-first page

The landing page says "No external services, no data leaving your network" directly under copy that leads with the managed cloud. That's only true for self-hosting.

**Expected:** scope the claim to self-hosting, or remove it.

### U-28: Pricing contradicts itself

The Pricing intro says "Same features, same limits", then lists "Up to 10 users" for Cloud and "No user limits" for Self-Hosted. The Self-Hosted CTA says "Get Started" but sends you to GitHub with no warning. The landing page also describes MCP as being "in the managed cloud", while the MCP docs talk about "your instance", so it isn't clear whether self-hosters get it.

**Expected:** accurate copy, and label the CTA "Self-host on GitHub".

### U-29: Docs make signed-in users feel logged out

**Reproduce:** while signed in, click API Docs or MCP in the sidebar.

**Actual:** the app is replaced in the same tab by the marketing layout, which shows "Get Started" and "Sign In". There's no "Back to app". "Home" does return you to Workspaces, but that isn't obvious.

**Expected:** show signed-in navigation with a clear route back to the app, or open docs in a new tab.

## What worked well

- **Account isolation:** another account's workspace and memory returned 404 on web and API, including a new account reusing a deleted account's email.
- **Script injection:** `<script>`, `onerror` and `javascript:` were all neutralized in rendered Markdown and escaped in previews.
- **Search:** handled odd input such as `"`, `(`, `AND`, `title:`, `%%%` and `<script>` without errors. Operators worked and matching was case-insensitive.
- **Delete Memory dialog:** names the memory and states how many versions and links go with it. Use this as the model for U-32.
- **Unsaved-changes guard:** warns before leaving a dirty editor.
- **Sign-in:** returns you to the page you originally asked for.
- **Password reset:** the request screen doesn't reveal whether an email exists.
- **REST API:** the documented calls worked as shown, with clean error JSON for 401 and 404.
- **Data export:** the background job finished and offered a download with an expiry date. I didn't open the file.
- **Dark mode and phone layout:** clean on the main screens, with no horizontal page scroll on the pages I measured.

## Checked and not a bug

- **Blank mobile landing hero:** my screenshots caught a fade-in that completes in about 1.2 seconds. On slow connections the CTAs do arrive late, at around 1.5 seconds.
- **API 401s during testing:** my script sent an empty token. With the real token, everything worked.
- **`bin/dev` stopping when run without a terminal:** the Tailwind watcher exits without a TTY, and foreman then stops everything. This only matters for automation.
